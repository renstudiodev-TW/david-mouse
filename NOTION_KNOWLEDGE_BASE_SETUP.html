🤔 為什麼這樣設計？

網路上很多人分享「用 Notion 整理 AI 開發流程」會犯一個錯：過度設計。一開始就建 5 個 database、20 種 tag、複雜的 relation——結果用了 2 次就放棄。

我們反過來做：

  • ✅ 只建 1 個 database（Dev Sessions）
  • ✅ 每次開發產 1 個 DEV_LOG.md，直接 import 進去
  • ✅ 累積 5-10 筆之後，看資料反推需要哪些分類，再加 database
  • ❌ 不一開始建「Decisions / Patterns / Prompts」三個分類庫 — 沒資料時建分類是自欺欺人
💡 原則：先有資料、再有結構。Notion 強大在 database 可以隨時新增 property 跟 view，不要在空 database 上糾結結構。

📁 Step 1：建立新 Page 作為知識庫根目錄

1打開 Notion，在左側 sidebar 點「+ Add a page」

2命名為：🧠 RC's Dev Knowledge Base（或你喜歡的名字）

3icon 選一個（建議 🧠 大腦 / 📚 書 / 🛠️ 工具）

4cover 可省略

🧠 RC's Dev Knowledge Base ───────────────────────────── （這層是空白頁，等下會在裡面建 database）

🗂️ Step 2：建立「Dev Sessions」Database

1在剛建的 Page 裡，按 / 鍵，輸入 database

2選 「Table - Full page」（全頁面表格，比 inline 好用）

3名稱輸入：Dev Sessions

4icon 選 💻 或 ⚡

⚠️ 注意：選 "Full page" 不是 "Inline"。Full page 將來資料多了比較好操作，inline 會擠在 parent page 裡。

⚙️ Step 3：設定 Database Properties

進入 Database 後，預設只有 Name 跟 Tags 兩個欄位。我們要改成下面這 8 個 properties：

Property 名稱 Type 用途 選項範例
Name Title（預設） 專案/任務名稱 HeadMouse Helper
Date Date 開發日期（或日期區間） 2026-05-27
Status Status 專案狀態 In Progress / Shipped / Abandoned / Paused
Stack Multi-select 用到的技術 Python, Tkinter, ctypes, Win32, PyInstaller
Models Used Multi-select 協作的 AI model Claude Opus 4.7, Gemini 2.5 Pro
Project Type Select 專案類型 Desktop App / Web App / CLI Tool / Script / Demo
Repo URL GitHub / local 路徑 C:\Users\boren\Desktop\fordavicdmouse
Hours Spent Number 實際開發時數（自己估） 4.5

怎麼新增/刪除 Property

1新增 property：點 table 右邊最後一欄的 + → 選 type → 命名

2修改 property：點 column header → Edit property → 改 type 或選項

3刪除 property：點 column header → Delete property（預設 Tags 可以刪）

💡 Multi-select 小技巧：第一次輸入新標籤時直接打字按 Enter，Notion 會自動建選項。不用先去設定頁面手動建。

👁️ Step 4：建立 Views（不同角度看資料）

同一份 database 可以有多個 view。建議先建 3 個：

View 名稱類型用途設定重點
All Sessions Table 總覽，看所有開發紀錄 顯示全部欄位，按 Date 排序（newest first）
By Stack Board 看哪個技術做最多 Group by Stack（或 Project Type）
Active Table 進行中的專案 Filter: Status = "In Progress"

建立 View 的方法

1點 database 上方的 「+ Add view」

2選 view 類型（Table / Board / Calendar / Gallery / List / Timeline）

3命名 → 點「Create」

4在 view 設定裡加 Sort、Filter、Group

🤖 進階：用 Notion API 自動化（暫不需要）

當你累積到 30+ session 並開始嫌手動 import 麻煩時，可以做這個。現在跳過。

點此展開技術細節（明天先不用看）

原理

  1. 在 Notion My Integrations 建一個 internal integration，拿到 API token
  2. 把 Dev Sessions database 分享給這個 integration
  3. 寫一個 Python script 用 notion-client 套件，把 DEV_LOG.md 自動 push 上去

範例 script（將來用得到再寫）

from notion_client import Client
import os, frontmatter

notion = Client(auth=os.getenv("NOTION_TOKEN"))
DATABASE_ID = "xxx"

with open("DEV_LOG.md", encoding="utf-8") as f:
    content = f.read()

notion.pages.create(
    parent={"database_id": DATABASE_ID},
    properties={
        "Name": {"title": [{"text": {"content": "HeadMouse Helper"}}]},
        "Date": {"date": {"start": "2026-05-27"}},
        "Status": {"status": {"name": "In Progress"}},
    },
    children=[
        # 解析 markdown 轉 Notion block...
    ]
)

建議：等你做完 10+ session 再寫這個 script，否則只是 over-engineering。

🙋 常見問題

Q1：Notion 免費版夠用嗎？

夠。免費版的 block 數量上限對個人使用幾乎不可能用完。Block 限制只在「team workspace」才嚴格。

Q2：可以同步到手機看嗎？

可以。下載 Notion App，用同一個帳號登入，自動同步。

Q3：如果想匯出備份怎麼辦？

Settings → Settings & Members → Settings → Export content → Markdown & CSV。建議每季匯出一次當備份。

Q4：之後想加 tag「醫療輔具」可以嗎？

可以。在 Dev Sessions 新增一個 multi-select property「Domain」即可。一個 session 可以掛多個 domain tag。

Q5：如何快速搜尋之前做過某個技術？

在 Stack property 上 filter，例如 filter Stack contains "Tkinter"，會列出所有用過 Tkinter 的 session。
